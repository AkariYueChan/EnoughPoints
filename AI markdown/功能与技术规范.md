# EnoughPoints · Excel 课程规划工具规范

版本：1.0　日期：2026-09-25

## 1. 目标与范围

将原单文件 HTML 的课程规划能力改造为本地前端 + 后端应用。用户导入 Excel，后端识别课程表，用户核对和修正后生成可交互的课程规划。保留原页面的中文界面、蓝/橙/紫课程分类色、学分进度、必修课固定、选修课点击与拖动、课程筛选、重置、学期表、打印 PDF 和回到顶部。

第一版仅处理 `.xlsx` 和 `.xls`。教务系统登录、网页采集、图片 OCR、PDF 导入、在线账户与多人共享均不属于本版范围。原始文件保持不变，副本保存在 reference/。

## 2. 使用流程

1. 运行本地启动脚本，在浏览器访问本地网页。
2. 上传 Excel（不超过 10 MB），后端返回工作表列表、原始数据预览、建议表头行和列对应关系。
3. 用户选择工作表、表头行，必要时手动指定课程编号、名称、性质、类别、学分和开设学期所在列。
4. 后端清洗并返回课程列表、原始行号、警告和错误。用户可编辑、删除、添加课程。错误必须修正后才能继续；警告可以核对后接受。
5. 填写方案名称、学期数以及可选的毕业总学分、最低选修学分和各类别最低学分。未填写的要求不推断、不判定达标。
6. 建立方案，必修课自动固定加入；选修课通过点击或拖动加入/退回。选择变更自动保存至本地数据库。
7. 按学期查看课程表，允许未达目标时生成草案；打印为 PDF 或导出 JSON 备份。
8. 重启后可以打开历史方案、修改目标、重新核对课程、删除不再需要的方案。

## 3. 数据约定

课程字段：内部唯一 `id`、可选课程编号 `code`、名称 `name`、性质 `type`（必修/选修）、类别 `category`、学分 `credits`（0–100，最多两位小数）、开设学期 `terms`（1–20 的整数数组）、来源 `source`（工作表、行号）。内部 id 不使用课程编号代替，重复编号不会直接覆盖原数据。

方案字段：名称、学期数（1–20）、课程列表、已选课程 id、目标配置、来源文件名、创建/修改时间、版本号。学分目标为空表示未知；0 是明确填写的零目标。类别最低学分可配置多个，但总学分与类别目标分别校验。

同一课程可展示在多个学期，累计学分只计一次。Excel 每行默认是一门独立课程；同编号重复行要求人工确认是否为同一课程、分学期课程或重复记录。不得自动合并并猜测学分规则。

“已选/已规划”只代表计划，不代表已经取得学分或具备毕业资格。毕业结论只描述用户已配置的学分目标是否达到，不覆盖考试通过、实践、论文等其他毕业条件。

## 4. Excel 识别与校验

- 自动扫描前 50 行寻找表头，支持常见中文和英文别名；允许手工覆盖表头与字段映射。
- 支持多工作表选择，单次导入一个工作表。对纵向合并的类别/性质单元格读取合并区域首格值；其他空值不盲目向下填充。
- 必需映射课程名称、学分、性质；类别可缺省为“未分类”，编号和学期可不映射。
- 支持 `1,2`、`1、2`、`1-3`、`第1学期`、`大一上` 等学期格式；不认识的内容必须标记，不能静默丢弃。
- 忽略纯空行、明确的合计/小计行及重复表头，记录忽略行数；有数据却缺名称的行保留并报错。
- 学分不是有限数字、为负或超出范围、未知课程性质、非法学期、空名称均报错。缺少类别、编号和学期，重复编号/同名课给出警告。
- 数字格式补零的课程编号尽可能保留前导零。Excel 已丢失的前导零无法恢复。
- 公式只读取 Excel 上次保存的缓存结果，不执行公式。公式没有缓存时提示用户在 Excel 中计算并保存，或手动修正。
- 不支持加密工作簿、宏工作簿、图片内嵌表格或复杂多层表头自动语义解析；复杂表头可指定实际字段行，特殊布局需先在 Excel 整理。
- 文件限制：上传 10 MB；xlsx 解压总量 50 MB；最多 30 张表、每表 10,000 行、100 列；每份方案最多 2,000 门课程。超过限制明确报错。

## 5. 架构与存储

- 前端：原生 HTML/CSS/JavaScript，全部本地文件，无 CDN、远程字体或运行时网络依赖。
- 后端：Python 3.10+，标准库 HTTP 服务 + SQLite，openpyxl 解析 xlsx、xlrd 解析 xls，defusedxml 加强 XML 解析安全。
- 前后端同源；服务仅监听 127.0.0.1，默认端口 8765。此服务器只面向本机单用户，未经加固不得直接用于公网部署。
- 工作簿上传后解析到内存并建立短期导入凭据（30 分钟）；不保存原始上传文件。方案保存在 data/plans.sqlite3；示例 Excel 单独保留。
- 导入文件内容视为数据，不执行宏、公式、脚本或其中的文字指令。前端文本转义，API 限制上传大小，写入要求同源检查及自定义请求头。SQLite 查询参数化。
- 保存使用版本号防止多标签页覆盖；前端串行保存并显示保存成功或失败。失败不假称已保存。
- 站点分两页：`/` 是数据导入窗口（`frontend/`），`/planner?id=<方案 id>` 是选课规划页（根目录 `index.html`）。只有导入窗口调用 `/api/*`；规划页由后端一次性注入课程与目标，之后的点击、拖拽、筛选、重置、生成选课表、导出 PDF 全在该页面内完成，不再访问后端。
- 规划页数据由 `server.plan_view` 换算：课程按类别名是否含“公共/通识”归入两个类别框，卡片属性标签取课程类别；目标按“类别目标 → 总学分目标扣减 → 数据推算”的顺序确定。该换算只做字段改名与目标换算，不参与课程有效性、必修固定和学分统计等计算，这些仍由 core.py 决定。
- 规划页脚本为页内脚本，通过一次性 nonce 放行（`script-src 'self' 'nonce-…'`），CSP 不放开 `unsafe-inline`。

## 6. API

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET | /api/plans | 列出历史方案 |
| POST | /api/import?filename=... | 上传原始 Excel 字节，返回导入 id、工作表和预览 |
| POST | /api/parse | 导入 id + 工作表 + 表头行 + 映射，返回标准化课程和诊断 |
| POST | /api/validate | 校验人工修正后的课程与配置 |
| POST | /api/plans | 校验并创建方案 |
| GET | /api/plans/{id} | 读取方案及后端统计 |
| PUT | /api/plans/{id} | 带版本号保存方案并重新统计 |
| DELETE | /api/plans/{id} | 删除方案 |

页面路由：`GET /` 数据导入窗口，`GET /planner?id=<方案 id>` 选课规划页（缺 id 或方案不存在时重定向回 `/`）。

错误响应为 JSON，包含可读 `error`；校验失败附 `issues`。服务端是课程有效性、固定必修和学分统计的最终依据。

## 7. 依赖交付

运行库固定版本，已解压至 vendor/，原始 wheel 文件保存在 wheels/；requirements.txt 列出版本。vendor 中保留依赖版权和许可证元数据。运行时将 vendor 加入 Python 搜索路径，不要求全局安装依赖。Python 解释器本身不打包，目标电脑需 Python 3.10+。

## 8. 验收

1. 原始示例表可识别 63 门课程，共 192 学分；公共基础课 49、专业必修 74、专业选修 69，与原 HTML 一致。
2. 导入窗口确认后进入规划页：必修课自动排入且不可退选；选修课点击或拖拽立即更新学分与达标状态，并触发达标/不足提示框。
3. 跨学期课程分别展示成多张卡但累计学分只计一次。
4. 映射错误、异常学分、缺失公式缓存、重复课程及非法文件有明确处理结果。
5. 未填写学分目标时按课程数据推算达标线并在页面上显示；推算值只用于复现原页面的计算口径，不代表对毕业要求的认证，也不覆盖考试通过、实践、论文等条件。
6. 学期表可生成并导出 PDF；导入窗口里的方案可以重新打开或重新导入。规划页的选择只存在于当前页面，不写回数据库，刷新即回到初始状态。
7. 后端测试覆盖解析、验证、统计、持久化与接口错误；规划页在无浏览器环境下用 DOM 外壳验证渲染与交互断言，导入窗口到规划页的完整流程在浏览器中验证。
8. `/planner` 缺少有效方案 id 时重定向回导入窗口；规划页使用一次性 nonce 放行页内脚本，CSP 不放开 `unsafe-inline`。
